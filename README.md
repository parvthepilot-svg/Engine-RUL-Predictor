# ✈️ Engine Remaining Useful Life (RUL) Predictor

An end-to-end machine learning pipeline that predicts how many flight cycles a jet engine has left before it needs an overhaul — built on NASA's C-MAPSS turbofan degradation dataset, and evaluated using the same safety-weighted scoring function NASA designed for this exact problem.

> A software implementation of **Condition-Based Maintenance (CBM)**, one of the most active areas of investment in modern MRO (Maintenance, Repair, and Overhaul) engineering — built entirely in software, with no hardware involved.

## The Problem

Airlines face a constant trade-off: retire an engine component too early and waste money on a part that still had useful life left; wait too long and risk a failure in service. Condition-Based Maintenance solves this by continuously reading an engine's sensors — the aviation equivalent of vital signs — and predicting **Remaining Useful Life (RUL)**: how many more flights an engine can safely fly before it needs attention.

This project builds a simplified version of that system using NASA's C-MAPSS (FD001) dataset — simulated but physically realistic turbofan sensor data, generated by NASA specifically because real run-to-failure engine data is almost never available publicly.

---

## Why This Isn't Just an RMSE Leaderboard Project

Most projects that touch this dataset stop at "train a model, report RMSE." This one spends real effort on the harder, more domain-relevant parts:

- **Engine-level train/test split.** Rows are split by `unit_number`, not randomly — a random split would let a model see cycle 50 of an engine during training and cycle 51 of the *same engine* during testing, silently leaking the answer.
- **A physically-motivated capped RUL target.** Labels are capped at 125 cycles, because distinguishing "280 cycles left" from "300 cycles left" is both statistically noisy and operationally meaningless — both just mean *healthy*.
- **NASA's own asymmetric safety scoring function**, reimplemented from the original C-MAPSS paper (Saxena et al., PHM08), which penalizes *late* predictions (telling a mechanic an engine has more life than it really does) far more heavily than *early* ones — because in aviation, those two errors are not equally bad.
- **Directional bias analysis by life stage**, not just an aggregate error number — the model's tendency to over- or under-predict is measured separately for near-failure, mid-life, and healthy engines, because *where* a model is wrong matters as much as *how often*.
- **A cycle-scrubbing dashboard**, not a single-shot predictor. Since this test data records every engine through to actual failure, a dashboard that only ever showed each engine's *last* recorded row would report every single engine as critical, regardless of which one you picked. The slider fixes that — you can inspect any engine at any point in its life, and the dashboard openly flags where its own predictions are least reliable.

## Results

**Model comparison on held-out test engines (81–100, never seen during training):**

| Metric | Random Forest | XGBoost |
|---|---|---|
| RMSE (cycles) | 19.18 | **18.77** |
| MAE (cycles) | 14.24 | **13.96** |
| R² | 0.706 | **0.793** |
| NASA Asymmetric Score (avg penalty, lower = safer) | 14.41 | **12.75** |

XGBoost was selected as the deployed model — it won on every metric, including the safety-weighted one.

**Directional bias by true-RUL zone (XGBoost):**

| True RUL Zone | Mean Signed Error (cycles) | Interpretation |
|---|---|---|
| 0–25 (near failure) | +3.53 | Small late bias — best-behaved where it matters most |
| 26–50 | +12.01 | |
| 51–75 | **+13.76** | Worst zone — largest late/optimistic bias |
| 76–100 | +5.01 | |
| 101–124 (healthy) | −8.45 | Early bias — safe direction |

**Key finding:** the model is most trustworthy exactly where trustworthiness matters most — near actual failure — and least reliable in the ambiguous mid-life zone, where engines' individual degradation rates diverge the most. The dashboard surfaces this directly: any prediction landing in the 51–75 cycle range triggers an on-screen note explaining that it's likely optimistic.

## Dataset

**NASA C-MAPSS (FD001)** — Commercial Modular Aero-Propulsion System Simulation. Contains simulated sensor readings (temperatures, pressures, rotational speeds) from 100 turbofan engines, each run from a healthy starting condition to a simulated failure point, under a single operating condition and failure mode.

Source: NASA Prognostics Center of Excellence Data Repository.

Reference: A. Saxena, K. Goebel, D. Simon, N. Eklund, *"Damage Propagation Modeling for Aircraft Engine Run-to-Failure Simulation,"* International Conference on Prognostics and Health Management (PHM08), 2008.

---

## Pipeline Overview

| Stage | What Happens |
|---|---|
| 1. Data Loading & EDA | Load raw sensor logs; identify 14 of 21 sensors that show genuine degradation trends |
| 2. Feature Engineering | Standardize sensors; add 5-cycle rolling averages, grouped per-engine to avoid cross-engine smoothing |
| 3. RUL Labeling | Calculate true remaining life per cycle; cap at 125 to focus the model on the operationally meaningful range |
| 4. Train/Test Split | Split by engine ID (80 train / 20 test) to prevent data leakage |
| 5. Modeling | Train Random Forest and XGBoost regressors; compare |
| 6. Safety Evaluation | Score both models with NASA's asymmetric function; break down bias by RUL zone |
| 7. Dashboard | Interactive Streamlit app for engine-level inspection |

All steps 1–6 are in `Main code.ipynb`. Step 7 is `app.py`.

## Model Transparency

Rather than treating the model as a black box, this project explicitly surfaces its own limitations:

- The dashboard's cycle slider lets you verify predictions across an engine's *entire* life, not just a single snapshot.
- A built-in warning appears automatically whenever a prediction falls into the 51–75 cycle zone, the model's empirically weakest range, so a maintenance decision is never made on an unqualified number.

---

## Limitations

- Trained on **simulated**, not real-world, sensor data.
- Covers a **single failure mode** (HPC degradation) under a single operating condition (FD001 is the simplest of four C-MAPSS subsets).
- Does not account for real-world factors like manufacturing variance between physical engines or the effects of maintenance events between recorded flights.

These limitations are inherited from the dataset design itself (see Saxena et al., PHM08) and are stated here deliberately — understanding a model's limits is as important as reporting its results.
